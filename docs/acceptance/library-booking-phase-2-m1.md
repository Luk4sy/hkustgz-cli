## 本轮实现

- `rules.ts`：纯规则判定模块，供后续预览消费；检查学校时区、规范日期、同日未来区间、人数上下限、时长、开放、占用/缓冲、可用段起点的步长与已证实整天提前范围。返回可解释pass/fail/unknown。整体只有blocked/unknown，不能返回ready；本轮没有新增规则查询或预览命令。
- `identity.ts`：新鲜来源主体仅保留于闭包；比较账号变化，原始账号及认证信息不可枚举/输出；可用调用者提供的随机密钥派生HMAC绑定摘要。M1不创建持久密钥或操作凭据，不将原始身份落盘。
- `inspection-reader.ts`：复用已观察的正常`disCaseUserInfo` GET刷新与本人表格GET读取。选择全部正常可见状态选项，保留明确数值筛选口径；请求前后新鲜主体核验，身份证据失败单独标记；HTTP错误保留Retry-After。只投影必要记录字段、所有权布尔及成员数量，不输出uuid、账号、成员名册或其他诊断正文。
- `detail.ts`：按精确来源ID在指定日期范围分页查找，稳定验证窗口/总数/筛选、去重并保留可信partial；身份失败则丢弃全部先前数据。缺失区分`not_found_in_scope`与partial下的`unknown`，均不表示已取消。所有权成立也不证明可取消，取消状态仅blocked/unknown。
- 源码新增`booking detail --provider library --id <id> [--from <date> --to <date>]`命令定义及帮助。范围沿用默认7天、最多31天、to不包含当天。**该能力仍pending**：尚无新实现完整正向现场详情验收，不借用mine的verified状态放行。

既有mine仍使用8454筛选，原17项verified能力不变；源码增加detail后为20项总能力、3项pending。实际已安装alpha.3仍为原19项能力，本轮未更新实际CLI/Skill、版本或候选包。
