# 登录后账号与规则核对，以及操作门槛修订提案

日期：2026-11-02，Asia/Shanghai。状态：**只读调研完成；Spec 修订待用户审查，尚未实施。**

依据：[第二阶段 Spec](../superpowers/specs/2026-11-01-library-booking-phase-2-spec.md)、[原规则证据](library-booking-phase-2-rules.md)、[真实单次创建/取消记录](library-booking-phase-2.md)。本次用户明确要求检查登录后能获得的权限和规则，据此调整 Spec，完成后停下审查。

## 1. 范围与方法

- 使用项目已有 `withSession` 专用 Chrome profile；没有读取或复制日常 Chrome Cookie。实际 CLI 版本核对为 `0.1.0-alpha.4`，与已加载 Skill 一致。
- 内置浏览器首页导航后，读取页面连续超时，未据此判断账号失效；随后改用项目已有会话模块完成只读观察。
- 正常打开 `https://libroombooking.hkust-gz.edu.cn/#/ic/home`，监听页面自身的 GET 响应；再进入 `#/ic/userinfo` 和已返回目录中的楼层。
- `roomMenu` 实际返回一、三、四、五楼，ID 分别为 5、2、1、4。四楼观察使用来源 ID 1，不从楼层数字推导 ID。
- 对图书馆 `/ic-web/**` 加只读拦截，仅允许 GET/HEAD/OPTIONS；本轮所有完成的会话写入拦截触发均为 0。未点击提交、取消、签到、支付或上传，未新建业务预览/操作凭据。
- 观察包含账号字段的类型、必要状态、规则白名单及本人默认成员的布尔比较；未记录账号标识、Token、成员名册、个人截图或原始认证响应。账号样本只适用于本次会话，不用于推断其他同学权限。
- 正常表单组件已挂载但对话框未打开。读取其数据结构与本人默认成员匹配结果，不把它计作“完整表单可提交”或具体未来时段可选的证据。个人中心的信用入口可见，本轮未进入信用明细，不能宣称取得信用余额。

以下是研究观察，不是 CLI 产品测试，也不是新的服务端创建/取消验收。

## 2. 登录后实际能读到什么

所有路径均相对于官方 origin `https://libroombooking.hkust-gz.edu.cn`，仅列 pathname，不保存身份或查询票据。

| 来源 GET | 本次观察 | 可采用的结论 | 不能推出的结论 |
|---|---|---|---|
| `/ic-web/auth/userInfo` | HTTP 200/code 0；服务侧主体字段存在；`status=1`、`localstatus=1` | 可绑定当前本人，刷新核对同一主体；未命中前端成员选择的 status/localstatus=2 禁用条件 | 不等于对所有资源具有预约权，也未证明所有状态值语义 |
| 同一响应 | `useQuota=null`、`roleId=null`、`roleLevel=null`、`permsSet=[]`、`expiredDate=0` | 字段存在；该样本没有可解释的剩余预约次数或资源权限清单 | null 不等于无限额度；空 permsSet 不等于无权；0 不自动解释为永不过期 |
| `/ic-web/reserve/punishInfo` | HTTP 200/code 0、空数组 | 此次处罚查询没有返回记录 | 不证明其他资格条件均通过，不证明永远无处罚 |
| `/ic-web/roomMenu`、`/ic-web/reserve` | 当前账号能读取楼层及资源；资源含 `onlyView`、适用 `resvRule`、人数、开放段和占用 | 可直接用学校返回的目标资源规则进行本地核对；`onlyView=true` 明确阻断 | 房间出现在目录中不等于可以创建；只读成功不是业务许可 |
| `/ic-web/reserve/count` | code 0、data 为数值 | 正常个人中心存在预约计数读取 | 本次未证明其完整筛选/计数口径，不命名为“剩余额度” |
| `/ic-web/reserve/resvInfo` | 正常本人列表 GET；响应正常 | 可按已验证筛选与日期范围读本人记录 | 不覆盖已删除记录或未知学校计数范围，不能自行算出完整额度 |
| `/ic-web/sysConfig` | code 0，81 项配置；部分含说明 | 可取得主题、验证码、人数例外主题、取消显示差值等配置 | 全局参数不能直接覆盖目标房间规则；位掩码不能当布尔值 |
| 单次研修间组件 | `selectAccNoList` 仅含当前 `userInfo.accNo`，比较结果 true | 本人单成员默认绑定有现场证据，无须通过成员搜索枚举本人 | 不验证额外参与人的身份和资格；未打开对话框不等于已完成表单预检 |

账号响应还包含与本次业务无关的个人属性，研究脚本只投影字段类型，不保存其值；实现时也不得整体导出该响应。

## 3. 目标规则样本和配置

### 3.1 四楼 403 研修间

正常楼层页面返回：

| 条件 | 来源值 | 使用方式 |
|---|---|---|
| 人数 | `minUser=1`、`maxUser=2` | 本人 1 人符合该人数范围，不推广到讨论间 |
| 展示限制 | `onlyView=false` | 未被该标志阻断；不是全部资格证明 |
| 开放段 | 08:00–23:00、`openLimit=1` | 仅为此次页面日期样本；实际预约须重读目标日期 |
| 时长 | `minResvTime=15`、`maxResvTime=120` | 按来源包含端点的区间核对 |
| 步长 | `timeInterval=5`、`freezingTime=0` | 按目标空闲段与来源步长计算；不能替换为全局 10 分钟 |
| 提前范围 | `latestResvTime=0`、`earliestResvTime=20160` | 原正常页面代码解释为学校日期 0–14 天；不是精确现在起 336 小时 |
| 取消/签到 | `cancelTime=10`、`earlyInTime=10`、`resvAfterNoticeTime=10` | 取消政策与签到后果沿原正式政策和须知解释，不单凭数值推断服务器临界行为 |
| 规则掩码 | `limit=260` | 4 已解释，256 本轮仍未解释；不改名为已知规则 |
| 其他配置 | `seriesTimeLimit=1440`、`deadlineTime=1`、`rangeNum=2` | 没有可证明的完整计数口径，不实现为每日/每周/可持有数 |
| 维护 | `maintenanceTime=null` | 本次字段为空，不等于已验证所有维护机制 |

对照样本：三楼页面此前正常读取的 302–316 首批讨论间为 2–5 人；一楼 Exhibition Hall 为 1–50 人、`onlyView=true`，使用不同规则。不能将“学校已登录”或研修间规则套用到这些资源。未对这些对照样本执行预约。

单次研修间的 `submitBtn` 先运行 `ruleForm.validate`、检查起止字段，再调用已取证的创建包装；失败显示来源消息。**在这段已检查路径及本轮观察到的正常 GET 中，未发现独立返回“本次账号资格及剩余额度全部通过”的只读预检。**这不是全系统不存在此接口的证明，不尝试猜测或调用候选端点。

`openFun` 将成员选项及已选成员初始化为当前主体；成员搜索 `remoteMethod` 将 `status===2 || localstatus===2` 的候选禁用。默认本人绑定与其他成员搜索应分开实现，不能为了验证本人而枚举他人。

原位 256 仍未得到标签；当前单次表单 `limit` 展示仅列 0、1、2、4、8、16、64、128。由此只能说“前端没有在这张标签表解释它”，不能说服务端忽略它或它没有副作用。

## 5. Spec 修订建议与取舍

维持“所有底层位含义、计数口径和服务器边界全部解释后才能尝试”的方案，会要求客户端复制学校后端，也超出了正常网页提供的信息。另一方面，仅凭登录或按钮存在放行，无法绑定主体、目标和已知后果。

本提案采用：**限定已取证的正常单次流程，检查已知且可读条件，明确列出由学校最终裁决的限制；未知副作用与协议变化继续阻断。**这是根据本次调研提出的政策调整，须用户审查，不冒充规则缺口已经补齐。

| 分类 | 处理 |
|---|---|
| 可读取且有语义的条件 | 必须读取并核对；缺失/过期/冲突阻断，失败不得改为警告 |
| 学校最终裁决、没有已验证只读完整判据的资格/额度/跨系统冲突 | 标记 `server_enforced`，说明尚未预确认；不能标 pass、无限额或有权限；具体用户确认后最多提交一次，接受学校明确拒绝 |
| 会影响目标、付款、参与人、信用后果或动作流程的不明条件 | 阻断；不能笼统标 server_enforced 来绕过 |
| 未解释内部位，但目标属于已取证的同一单次规则族、规则/配置形状及正常表单行为均核对一致 | 可以不以“必须解释所有内部位”单独阻断；记录未解释值及适用边界。不能把 260 或所有未知位加入全局白名单 |

首批建议限于**本人单人、四楼研修间已取证规则族、单资源/同日连续时段、无附件/附加服务/验证码/付款的正常单次创建**；具体房间、目标日期和规则快照需逐次核对。取消仅先支持精确本人记录、已知可取消状态且开始前严格超过 10 分钟的保守窗口；恰好 10 分钟、已开始或来源后果不清不试提交。

`ready` 仅表示“本地及可读取前置检查满足，已披露学校待裁决项，可请求用户确认后尝试一次”，不是资格获批或预保证成功。对账号限额的检查不应靠先创建再取消探测。
