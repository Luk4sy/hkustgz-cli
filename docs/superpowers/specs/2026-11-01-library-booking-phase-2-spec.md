## 3. 方案选择

| 方案 | 取舍 |
|---|---|
| 同一浏览器进程展示后等待终端输入确认 | 交互直观、少跨进程状态；不利于Agent分步调用、进程中断后恢复与重复保护 |
| **预览与提交分离，使用本地操作凭据（本稿建议）** | 确认绑定明确参数、可跨进程核对结果；需要新增小范围、本机私有的操作状态存储 |
| 直接创建，出错后重试或依赖网站自行防重 | 当前服务端语义尚未验证，无法满足重复保护与不确定结果要求，不作为本期方案 |

沿用TypeScript/ESM、Commander、Zod、Playwright、现有会话/锁与脱敏机制。仅为图书馆闭环增加必要接口，暂不建设通用的全校交易平台。

## 4. 命令与用户流程（拟议，尚未实现）

### 4.1 既有命令

`booking providers`、`booking rooms/availability/mine --provider library`继续保持只读。`mine`默认过滤8454及原返回字段不变。内部结果核对不能借用这个默认过滤判断预约已取消或不存在。

### 4.2 新命令提案

| 命令 | 职责 | 学校业务写入 |
|---|---|---|
| `booking detail --provider library --id <id>` | 读取本人有权查看的指定预约及来源状态、可取消判据 | 无 |
| `booking preview --provider library --input -` | 从stdin读取预约意图，核对条件，返回预览及本地操作凭据 | 无 |
| `booking create --provider library --operation <id> --confirm <digest>` | 对该预览执行一次创建尝试并回查 | 明确确认后才有 |
| `booking cancel-preview --provider library --id <id>` | 读取目标预约、确认本人取消权限，产生取消预览 | 无 |
| `booking cancel --provider library --operation <id> --confirm <digest>` | 对该预览执行一次取消尝试并回查 | 明确确认后才有 |
| `booking operation <id> [--refresh]` | 本地查看操作状态；`--refresh`只做服务端结果核对 | 无 |

这里的“无学校业务写入”允许为分步提交保存最小本地预览凭据，存储范围见第8节。不得通过点击时段建立学校草稿来获取预览。

所有命令有`--help`，默认JSON并支持table。操作ID是本地凭据ID，预约ID是来源记录ID，两者不可混用。不得接受任意URL、请求方法或认证头。帮助/版本不启动浏览器。

### 4.3 预约意图

```ts
interface LibraryBookingIntent {
  roomId: string;                  // 来源devId
  startsAt: string;                // 带时区的ISO时间
  endsAt: string;                  // 带时区的ISO时间
  participantIds: string[];        // 经过来源校验的真实参与人；含本人规则据证据确定
  purpose?: string;                // 仅在学校需要时提供
}
```

以`Asia/Shanghai`解释并规范化时间，使用[start,end)，拒绝非法日期、过去时段、跨学校日期及首批不支持的周期/批量意图。人数计算、本人是否自动包含、参与人去重、同名识别及用途约束必须按学校来源确定；有效参与人列表在预览中完整体现，不能悄悄补人。

stdin避免参与人和用途落入shell历史；不在日志回显输入。上面是内部意图类型，不是学校请求体；M0确认映射后实施。字段若包含凭据或任意目标URL，拒绝而非透传。

### 4.4 确认规则

预览展示：房间及位置、起止时间、时长、实际人数、必要参与人、用途、资格/规则检查、已知审批要求及服务自带的必要副作用、费用判据、预览截止时间。姓名等展示仅限该次操作所需，不输出与预约无关的账户信息。

可提交预览返回`operationId`与`confirmationDigest`。待确认参数任何一项变化，都必须重新生成预览并重新取得用户确认。没有`--confirm`、摘要不匹配、预览过期或来源规则/资格变化时不提交。

Agent读取到摘要不代表获得业务授权。用户须先看到该预览并明确同意该次创建或取消；之后运行对应命令不再重复询问。用户直接输入完整的提交命令及匹配摘要，也构成对该次预览的明确确认。不提供绕过预览的`--yes`或自动接受所有变更的开关。

## 5. 规则、主体与取消权限

| ID | 要求 |
|---|---|
| L2-R01 | 开放、有效占用与该目标规则类型的相关限制均有证据，才允许预览为ready；有未知关键项则blocked/unknown |
| L2-R02 | 检查关闭/维护、人数、资格、时长、步长、提前时间、本人已有预约限制等适用条件；只实现已证实的规则类型 |
| L2-R03 | 审批型资源的已知条件可在预览说明“提交申请”；创建记录成功不能说成审批通过或场地已获准使用 |
| L2-R04 | 新进程、最终提交前、结果核对时都核实同一服务侧主体；沿用正常SSO，不代填密码/验证码 |
| L2-R05 | 预览绑定本人主体、资源、时间、参与人、用途、动作和相关规则版本；提交时重新读取时效性条件 |
| L2-R06 | 可取消权以来源授权为准；出现在“我的预约”中不一定代表本人是创建者或有取消权 |
| L2-R07 | 已取消记录只读确认后返回already_cancelled，不再发送取消；取消窗口已过、审批/进行状态不允许时明确拒绝 |
| L2-R08 | 取消预览展示精确来源预约ID、房间、时间和已知后果；不得按列表序号、相似标题或最近一条记录猜目标 |
| L2-R09 | 规则检查与最终提交之间仍可能被其他人占用；接受明确的服务端冲突，不自动换房/换时间或再次创建 |

现有privacy规则关于不导出凭据保持不变。为防止换账号提交，允许新操作流程在内存读取最小、已验证的服务侧主体标识并立即派生本机主体绑定值；不输出、落盘原始账号、姓名、邮箱或认证数据。具体标识来源在M0确认，不能以“页面仍打开”或Cookie可用代替本人判据。

## 6. 操作状态与结果协议

### 6.1 状态

本地生命周期：`prepared → dispatching → resolved`；过期但尚未发出的预览为`expired`。崩溃遗留`dispatching`在下次检查时按结果不确定处理，不能当作未发出。

业务结果独立表示：

| outcome | 含义 |
|---|---|
| `not_attempted` | 仅预览或本地/前置检查已阻止，未发出业务写入 |
| `confirmed` | 权威来源证明本次预期业务结果，见6.2 |
| `not_applied` | 已核实的来源拒绝或明确无副作用，能证明操作没有生效 |
| `already_cancelled` | 精确目标记录已取消，无需再次写入 |
| `unknown` | 写入可能已发出，但无法证明结果；只允许核对，不允许重新提交 |

`prepared`不等于已预约，来源`pending_review`不等于审批通过；`coverage=complete`不等于资格通过；它们不得混用。

### 6.2 权威结果确认

创建：取得正常提交应答中的有效来源ID/关联凭据，并从本人权威记录回读，核对主体、目标房间、时间、参与人与必要业务状态。只有业务成功码而无可靠回读，不报告confirmed。

创建应答丢失时：优先使用已验证的服务端幂等/关联机制。如果只找到一条时间和内容相似的新记录，不能直接认定为本次请求所创建。可报告最小候选信息并保持unknown；存在多个候选、并发其他客户端、分页/筛选不完整时也必须unknown。未取得可靠证据前不自动完成本地状态。

取消：按精确来源ID回读到已取消状态，或取得M0验证可作为最终证据的取消凭据。列表缺失、空结果、只查8454过滤、404或本人失去查看权限，均不能单独证明取消成功。若应答丢失但精确记录已被权威标为取消，可确认期望结果并说明依据。

`operation --refresh`不会创建或取消任何记录。unknown不能通过普通清理、过期、重新生成相同预览或重启CLI消失；人工核对需提供可验证的来源证据，不能仅凭“再试一下”把它改成not_applied。

### 6.3 新命令结果类型

`booking detail`采用既有只读QueryResult。预览、创建、取消与operation命令采用独立`OperationResultSchema`，`meta.schemaVersion='1'`、`meta.kind='operation'`；这是新增协议类型，**现有QueryResult、ControlResult和错误输出保持原样**。CLI按命令声明的结果类型校验，不把操作硬套成分页查询。

操作成功对象为`{ok:true,data:OperationData,meta}`，失败对象为`{ok:false,data:OperationData|null,error,meta}`。能够确定操作状态时必须保留data；参数解析失败、操作凭据不存在或损坏且无法可靠确定动作时才允许data=null，不猜测action或生成虚假操作ID。

```ts
interface OperationData {
  operationId: string | null;
  action: 'create' | 'cancel';
  lifecycle: 'prepared' | 'dispatching' | 'resolved' | 'expired';
  outcome: 'not_attempted' | 'confirmed' | 'not_applied' | 'already_cancelled' | 'unknown';
  eligibility: 'ready' | 'blocked' | 'unknown';
  reservationId: string | null;
  sourceStatusCode: number | null;
  approvalState: 'not_required' | 'pending_review' | 'approved' | 'rejected' | 'unknown';
  confirmationDigest?: string; // 仅可提交预览返回
  expiresAt?: string;
  checks: Array<{id:string;state:'pass'|'fail'|'unknown';reason:string}>;
}
```

实际预览还需包含4.4列出的用户可审查字段；操作核对回执仅输出必要字段，不能附任意响应或账户对象。成功/失败均为单个JSON对象；业务错误仍保留必要的`data`操作状态，table同样展示未知结果、来源状态、下一步。错误`retryable=false`不得被通用网络错误覆盖。

ready预览、confirmed、already_cancelled及正常本地状态读取退出0；预览有明确规则阻碍为BOOKING_RULE_BLOCKED退出4，因关键来源证据缺失而unknown退出6，不产生可提交摘要。参数/确认摘要/过期错误退出2；需登录3；无权4；前置只读网络/限流失败5；来源变化6；操作能力pending/unsupported为8；profile忙9。本地状态损坏/清理失败退出1。读取或刷新未决操作仍返回OPERATION_UNCERTAIN/10并保留data，不因只读查看而把未决状态表示为成功。

新增拟议错误：`BOOKING_CONFLICT`、`BOOKING_RULE_BLOCKED`退出4；`CONFIRMATION_REQUIRED`、`PREVIEW_EXPIRED`、`DUPLICATE_INTENT`退出2；`OPERATION_UNCERTAIN`退出10；`OPERATION_STATE_UNAVAILABLE`退出1。所有提交阶段的错误均不可通过重跑create/cancel自动恢复。

中断/终止保留130/143。若已可能发出写入，错误回执仍保留operationId与unknown；若来源结果已确认而本地清理失败，保留已确认的业务结果，同时返回清理错误和相应非0退出码。不得因关闭浏览器成功而把unknown变成成功，或因清理错误遗失业务回执。

## 7. 防重复、时序与失败处理

| ID | 要求与可验证行为 |
|---|---|
| L2-T01 | 预览有效期默认300秒；使用绝对截止时间。最终提交必须重新检查主体、关键规则、权限及预览绑定 |
| L2-T02 | 同一操作凭据仅能从prepared原子转入dispatching一次；发送业务请求前必须持久化该状态，失败则不发出 |
| L2-T03 | 未证明服务端幂等前，创建/取消各只允许一次有副作用的尝试；不复用只读QueryPolicy的瞬时失败重试 |
| L2-T04 | 在同一CLI_HOME内，对同主体、同动作、同规范化意图建立重复保护；相同unknown/dispatching不能通过新operationId再次提交 |
| L2-T05 | 已确认有相同有效预约时，创建预览应给出已有记录而非再次创建；取消和重新预约始终是两次独立授权 |
| L2-T06 | 请求发出后的网络中断、超时、未知应答、进程崩溃均先进入unknown并仅做有预算的只读核对 |
| L2-T07 | 只有已取证证明“未生效”的来源拒绝才为not_applied；HTTP状态码或错误文字不能取代业务语义 |
| L2-T08 | 继续遵守同来源串行、自发请求至少500ms、单次等待30秒及总预算；来源正常页面自身请求不强制改写 |
| L2-T09 | 只读核对默认90秒总预算、沿用20页/2000条及partial语义；额度耗尽不能放宽成成功 |
| L2-T10 | 写入动作与核对共用一次90秒截止，浏览器清理仍额外最多5秒；预算不足时不开始写入，已发出则留unknown供后续核对 |

本机防重不是跨设备、不同数据目录或学校网页的全局幂等保证。只有E2-05得到服务端证据时才可作对应承诺。

`operation --refresh`如需人工认证，返回LOGIN_REQUIRED，不一边等待登录一边继续提交。最终create/cancel不启动长时间交互登录，认证恢复后必须重新验证确认凭据或重新预览。

## 8. 最小本地操作凭据与隐私例外

分步提交和进程恢复需要新增`<CLI_HOME>/operations/`。这是针对**显式操作工作流**的窄范围状态例外，不把第一阶段的私人查询变为落盘缓存。

- 目录0700、文件0600；沿用归属、symlink/junction及路径检查；使用临时文件、原子替换与必要的持久化保证。
- 本机随机密钥仅保存在该私有归属目录，用于主体/意图绑定与摘要，不输出、不发给学校或其他服务。学校原始主体ID不落盘，不使用容易枚举的无密钥哈希代替。
- 有效预览可以保存提交所必需的规范化房间、时间、参与人ID和用途。这些是本机私有的预约意图，不写日志、Skill、仓库、npm包或遥测。原始HTML、查询全集、联系人名册、凭据及认证响应均不得保存。
- 过期且确定未发出的预览删除敏感载荷，仅保留必要的短期防重信息。已解决记录默认保留最小回执7天，完成载荷及时删除。为满足L2-T05，对已确认但尚未结束的创建，最小防重回执保留至默认7天与预约结束两者较晚者；不保留完整意图/预览，结束信息缺失时不得自动解除防重，需权威核验。
- dispatching/unknown保留结果核对所需的最小资料，直到可靠核对完成；不得按7天自动删除并解除重复保护。后续压缩只能保留足以继续核对及防重的资料。
- 原`auth logout`清理浏览器会话的行为不变；不能顺带抹去unknown操作。npm卸载不删除这类状态。用户明确要求清除时需说明未决操作后果，不能用自动清理完成状态重置。
- 共享同一CLI_HOME的本地进程使用操作状态锁；与profile锁的顺序固定为“操作状态锁→profile锁”，释放顺序相反，操作结束必须释放。只读查询保持既有profile锁行为。

300秒和7天为随本文确认的默认值。最小回执包含operationId、动作、主体绑定、意图指纹、时间、结果、必要来源ID；敏感载荷是否删除不得影响未决状态判断。

## 9. 模块拆分与人工审查门槛

模块编号使用L2-M0至L2-M5，避免与第一阶段Task0–9混淆。以下是Spec的交付边界，**不是已批准的逐文件实施计划**。

### L2-M0：业务协议与规则证据

产物：E2-01至E2-06证据表、支持的规则类型、真实创建/取消的必要步骤及结果语义、待解决缺口。无产品实现，无能力升级。

真实写入只能使用用户确认的具体业务意图。需要用户本人在正常网页完成取证时，先展示房间、时段、参与人和预期后果；不能为了收集网络样本随意占位或代填其他人身份。真实创建/取消样本不足时如实交付“证据未通过”，不把静态代码或合成响应当成通过。

**停下来审查。**原门槛为M0关键证据通过并获授权继续，才开始后续业务实现；2026-11-01用户已按第11节调整允许M1只读先行，但M0仍未通过，未允许后续写入模块。其他缺口导致路线必须改动时先修订Spec。

### L2-M1：规则判定、主体绑定与本人详情

产物：可解释的pass/fail/unknown规则检查、最小主体绑定、目标预约权威详情读取、跨状态核对能力；既有mine默认行为不变。所有能力仍为只读。

验收：临时关闭、时间/人数/参与人/步长限制、账号变化、没有取消权、状态过滤漏记录等正常与失败路径；至少一个已支持规则类型有真实页面对照。

**停下来审查。**不进入凭据框架或发送创建/取消请求。

### L2-M2：预览、操作凭据与恢复框架

产物：create/cancel预览、过期及摘要校验、本地状态、锁、防重、只读operation核对框架。真实提交能力仍pending；测试使用可控写入替身验证绝不误发。

验收：本节存储例外、源条件不明、参数变化、换账号、过期、跨进程并发、崩溃恢复、敏感数据保护。预览/核对不得触发业务写入。

**停下来审查。**创建与取消暂不接真实提交。

### L2-M3：创建预约与结果核对

产物：显式确认后的唯一创建尝试、来源ID与详情回读、冲突/拒绝/应答丢失处理。审批状态与操作结果分别显示；未决状态不自动补发。

验收：单次真实创建须另有用户确认的业务预览；正常成功、最后瞬间被占、服务拒绝、丢应答、核对失败、信号与清理异常均覆盖。没有真实写入授权或可靠确认路线时不能将创建标为verified。

**停下来审查。**不自动开发或执行取消以“清理测试”。

### L2-M4：取消预约与取消结果核对

产物：精确目标与取消权限检查、显式确认后唯一取消尝试、已取消幂等返回、跨状态回查及未知结果处理。

验收：用户确认对具体来源预约ID取消；无权、过期、不能取消、已取消、结果丢失、分页/过滤导致缺失与真实确认路径。不能只凭记录从列表消失报告成功。

**停下来审查。**创建和取消模块分别验收，不以一个正常生命周期替代所有失败路径。

### L2-M5：闭环整合、Skill与新候选

产物：自然语言调用规则、操作结果协议与错误说明、版本一致的CLI/Skill及新候选。新的操作能力逐项有证据与状态，不沿用原17项测试总数推导新功能可用。

验收：从查询、预览、用户确认、创建及回读，到独立取消预览、确认、取消及回读的完整路径；原只读命令回归、真实/合成证据分离、打包排除私有operations、隔离安装与旧版升级。先前真实样本可在规则未变且链路仍有效时复用证据；需新真实操作时再次取得该次具体授权，不为增加测试次数重复占用资源。

**停下来审查。**用户验收后才安排本地安装同步；GitHub推送、合并及npm发布分别等用户指令。首批证明范围为个人macOS/Chrome alpha；Windows与其他账号仍须独立验收。
